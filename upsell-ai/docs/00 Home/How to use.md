# How to use the Upsell AI vault

Read the architecture and contracts before changing a phase. A phase is ready
for implementation only when its objective, owned behavior, E2E journey, and
acceptance criteria are explicit.

Use phase notes for delivery scope, architecture notes for stable boundaries,
contracts for observable behavior, and ADRs for decisions that future work must
not silently reverse.

When updating a phase, record the implementation status and the date in its
frontmatter. Do not mark a phase complete because its internal code exists; mark
it complete only after its E2E journey and safety criteria pass.
